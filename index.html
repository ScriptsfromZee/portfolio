01 · about

Quality is more than finding bugs.

I'm a QA Engineer who treats quality as more than bug-hunting. It's about understanding what a product needs to do, then proving it does that reliably under real conditions. My work covers functional, regression, API and exploratory testing across web and mobile platforms, usually inside fast-moving Agile teams.

Most of my recent experience sits in fintech and investment platforms, including Twikkie, Afristakes, Fraqvest and Paytton, where the cost of a missed defect is high and security testing matters as much as functional coverage. I've traced session-persistence and access-control issues back to their root cause rather than just logging them and moving on.

Outside client work, I lead Testers Connect, a QA community of 1,500+ members, where I run webinars and a knowledge-sharing initiative called Testers' Ink. I also apply AI-assisted workflows in my day-to-day testing, using structured prompts to speed up test case generation and defect documentation without cutting corners on coverage.

Goes beyond the obvious bugs

I don't stop at what the ticket asks for. Careful functional and exploratory testing has surfaced things like session-persistence flaws, OTP reuse and access-control gaps: real issues, not the kind of thing that shows up if you only test the happy path.

AI-assisted, not AI-replaced

I build and use structured AI prompts for test case generation, bug reports and regression planning, cutting documentation time without cutting coverage.

Documentation that holds up

Every defect I log has clear steps, expected vs. actual results and severity, written so a fix doesn't need a follow-up call.

05 · how i work

How I think about quality.

A test case that only covers the happy path tells you a feature can work. It doesn't tell you it works under the ways people actually use it. I try to test from the account that hasn't verified its email, the form filled in out of order, the request sent twice by accident.

Some of the most useful things I've found weren't obvious bugs: a session that outlived a password reset, an OTP a server accepted twice. Those don't show up if you only test what the ticket says to test.

The other half of the job is writing it down so someone can fix it without a follow-up call: clear steps, what I expected, what happened instead.

bug-report.log
Title: Session persists after password reset
Steps to reproduce:
  1. Log in on Device A
  2. Reset password from Device B
  3. Return to Device A, refresh /account
Expected: Device A session is invalidated
Actual: Device A stays logged in
Severity: Critical
